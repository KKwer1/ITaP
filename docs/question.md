### Что такое среда разработки и какие задачи она помогает решать?
Среда разработки (часто её называют IDE — Integrated Development Environment) — это программа, которая объединяет в одном интерфейсе инструменты для всего цикла работы: от написания кода до тестирования и отладки. Она помогает решать рутинные задачи: подсвечивает синтаксис (так код легче читать), предлагает автодополнение (IntelliSense в VS Code), позволяет быстро перемещаться по большому проекту, находить ошибки до запуска, запускать программу и пошагово отлаживать её, а также интегрируется с системами контроля версий и другими инструментами. В итоге разработчик меньше отвлекается на настройку отдельных утилит и больше фокусируется на логике приложения.

### Какие основные возможности Visual Studio Code используются при работе над проектом?
В VS Code много встроенных и расширяемых функций. Среди ключевых: подсветка синтаксиса, система автодополнения IntelliSense (подсказывает имена функций, переменных, показывает документацию), встроенный отладчик (точки останова, пошаговое выполнение), инструменты рефакторинга (переименование, извлечение функции), интеграция с Git (панель SCM для коммитов, переключения веток), поиск по проекту, поддержка расширений (для конкретных языков, линтеров, инструментов сборки).

### Для чего нужен встроенный терминал в среде разработки?
Встроенный терминал позволяет выполнять команды операционной системы прямо из среды, не переключаясь в отдельное приложение. Это удобно для запуска скриптов, сборки проекта, управления зависимостями, работы с Git (инициализация, клонирование, коммиты) и других задач. Часто есть полезные фишки: можно перетащить файл в терминал, чтобы вставить его путь, или запустить выделенный в редакторе фрагмент кода.

### Что такое каталог проекта и почему важно правильно организовывать файловую структуру?
Каталог проекта — это папка, которая содержит все файлы и подкаталоги, относящиеся к одному проекту. Правильная организация помогает:
- Не запутаться в большом количестве файлов.
- Упростить навигацию для себя и коллег (по именам папок сразу понятно назначение).
- Стандартизировать работу в команде (все знают, где лежат исходники, тесты, документация).
- Упростить автоматизацию (сборку, тестирование, деплой), если инструменты ориентируются на определённые пути. Часто используют логичные имена: src (исходный код), test (тесты), docs (документация), data (данные). 

### Что такое репозиторий Git и для чего он используется?
Репозиторий Git — это каталог в файловой системе, где хранятся файлы проекта, его история изменений, настройки и служебная информация (в скрытой папке .git). Он используется для отслеживания изменений в коде: позволяет сохранять «снимки» состояния проекта (коммиты), возвращаться к предыдущим версиям, работать над разными версиями кода параллельно (ветки), а также облегчает совместную работу в команде.

### Чем отличается инициализация репозитория от клонирования существующего репозитория?
Инициализация (git init) нужна, когда вы начинаете новый проект и хотите, чтобы Git начал отслеживать изменения в уже существующей локальной папке. В результате в папке появляется скрытая папка.

Клонирование (git clone) создаёт локальную копию уже существующего удалённого репозитория. При этом на машину копируются не только файлы проекта, но и вся его история изменений.

### Какие файлы обычно не включают в репозиторий и для чего нужен файл .gitignore?
В репозиторий часто не включают файлы, которые генерируются автоматически (например, файлы сборки, кэши, логи), файлы с конфиденциальной информацией (пароли, токены), а также файлы, специфичные для локальной среды разработчика. Файл .gitignore нужен именно для того, чтобы явно указать Git, какие файлы или шаблоны имён следует игнорировать — то есть не добавлять их в репозиторий при выполнении git add. 

### Что такое коммит и какую информацию он сохраняет?
Коммит — это основная единица в Git: он фиксирует «снимок» состояния отслеживаемых файлов в определённый момент времени. Помимо самих изменений, коммит сохраняет метаданные: информацию об авторе и дате, сообщение коммита, а также ссылку на родительский коммит (чтобы выстроить историю). На основе всей этой информации Git вычисляет уникальный идентификатор (хеш) коммита. 

### Почему важно писать понятные сообщения коммитов?
Понятное сообщение помогает другим разработчикам (и вам самим спустя время) быстро понять, что именно было изменено и зачем. Вместо общих фраз вроде «Код обновлён» лучше писать конкретнее: «Добавлен раздел в index.html», «Исправлен файл README». Это сильно упрощает чтение истории проекта и отладку. 

### Что такое Markdown и в каких случаях он применяется?
Markdown — это облегчённый язык разметки, который позволяет форматировать текст (делать заголовки, списки, выделять жирным или курсивом, добавлять ссылки, блоки кода, таблицы) с помощью простого синтаксиса. Его часто используют для написания документации (например, в README.md), комментариев в коде, сообщений в некоторых системах отслеживания задач, а также в блогах и на форумах. 

### Какие элементы Markdown используются для оформления заголовков, списков, таблиц, ссылок и блоков кода?
Заголовки: символ # перед текстом (количество решёток определяет уровень: # — H1, ## — H2 и т.д.).
Списки: для маркированных — -, * или +; для нумерованных — числа с точкой. 
Таблицы: вертикальные линии | для разделения столбцов, строка-разделитель из дефисов (можно добавить двоеточия для выравнивания столбцов).
Ссылки: квадратные скобки для текста ссылки, круглые — для URL ([Текст](URL)).
Блоки кода: тройные обратные кавычки (```) перед и после блока (можно указать язык для подсветки синтаксиса). Для встроенного кода внутри строки используют одинарные обратные кавычки.

### Для чего проекту нужен файл README.md и какая информация в нём обычно размещается?
README.md — это главный документ проекта, который даёт первое впечатление и помогает сориентироваться. Обычно в нём размещают: название проекта, краткое описание (что он делает и какую проблему решает), инструкции по установке и запуску, примеры использования, информацию о структуре проекта, данные о лицензии, контакты для связи, а иногда и рекомендации для контрибьюторов. Часто его оформляют с помощью Markdown для удобного форматирования.
