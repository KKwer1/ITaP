## Основная часть

### Что такое планировщик задач и зачем он нужен?

**Планировщик задач** — это программное обеспечение, которое помогает организовать и отслеживать задачи, проекты и дедлайны. Этот инструмент выступает цифровым аналогом традиционного ежедневника, но с расширенными возможностями автоматизации, уведомлений и коллаборации.

В основе работы планировщика лежит простой принцип: перенос мыслительных процессов из головы в систему, способную структурировать информацию. Это освобождает когнитивные ресурсы и снижает уровень стресса, связанного с попытками удержать в памяти множество деталей.

### Выделяемые команды

1. Владелец проекта  
2. Менеджер проекта  
3. Исполнитель проекта  
4. Ревьюер/QA  
5. Наблюдатель  

### Обязанности каждой команды

__Владелец проекта__ — ставит цели, утверждает приоритеты, следит за метриками, разрешает конфликты приоритетов.  
__Менеджер проекта__ — ведёт бэклог, распределяет задачи, контролирует сроки, ведёт отчётность. 
__Исполнитель проекта__ — выполняет задачи, фиксирует прогресс, сообщает о рисках.  
__Ревьюер/QA__ — проверяет результат, ставит замечания, подтверждает готовность.  
__Наблюдатель__ — следит за ходом проекта, даёт рекомендации. 

### Статусы задач

| Статус | Описание | Кто может ставить |  
| --- | --- | --- | 
| В разработке | Составление плана | Владелец/менеджер |  
| В очереди | Задача сформирована, ожидает начала работы | Вледелец/менеджер |  
| В работе | Исполнитель приступил к работе | Исполнитель |   
| На проверке | Задача выполнена, ждёт  вердикта ревью/QA | Исполнитель |   
| Завершена | Задача проверена, принята,  результат зафиксирован | Ревьюер/Менеджер |   
| Отложена | Задача временно приостановлена | Менеджер/Исполнитель |    
| Отменена | Задача больше не требует исполнения | Владелец/менеджер |  

### Сценарий добавления задачи

1. Создание черновика.
2. Заполнение обязательных полей:
3. Название: короткое, по шаблону: «[Тип] — [Объект] — [Действие]».
4. Описание: что нужно сделать, зачем, какие ограничения.
5. Критерии приёмки: 3–5 пунктов, по которым понятно, что задача готова.
6. Оценка трудоёмкости: часы или условные единицы.
7. Приоритет: Высокий/Средний/Низкий.
8. Добавление контекста: ссылки, макеты, файлы, теги, компоненты.
9. Назначение исполнителя.
10. Установка срока (Due date) и, при необходимости, зависимостей (блокирующие/блокируемые задачи).
11. Перевод в «В очереди». Задача попадает в общий список и видна команде.
12. Взятие в работу; выполнение и контроль.
13. Передача на проверку. Статус «На проверке», прикладываются результаты и чек-лист.
14. Приём. Ревьюер проверяет по критериям, либо подтверждает («Готово»), либо возвращает с комментариями.
15. Закрытие. Статус «Готово», фиксируется дата завершения, при необходимости — ссылка на результат.

## Сочетания клавиш

### Основные сочетания клавиш

| Действие | Сочетание клавиш | Категория |
| --- | --- | --- |
| Открыть файл | Ctrl + P | Файлы и навигация |
| Открыть палитру команд | Ctrl + Shift + P | Файлы и навигация |
| Открыть новое окно | Ctrl + Shift + N | Разработка 
| Закомментировать строку | Ctrl + / | Редактирование текста |
| Открыть встроенный терминал | Ctrl + ` | Работа с терминалом |

### Сочетание клавиш для закрытия терминала

```json
{
  "key": "ctrl+alt+m",
  "command": "workbench.action.terminal.kill"
}
```
